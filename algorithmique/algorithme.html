Chapitre 1

Penser comme un algorithme

Un ordinateur est très rapide, mais il n'a aucune imagination : il exécute des instructions, une par une, exactement comme elles sont écrites. Tout l'enjeu est d'écrire les bonnes instructions.

Qu'est-ce qu'un algorithme ?

Un algorithme est une suite finie d'instructions précises, exécutées dans un ordre donné, qui permet de résoudre un problème ou d'obtenir un résultat.

Vous en suivez tous les jours sans le savoir : une recette de cuisine, un tutoriel de montage de meuble, l'itinéraire donné par votre GPS ou les étapes pour publier une story sont des algorithmes.

Un algorithme transforme des entrées en sorties

Entrées

Les données de départ : ce qu'on fournit à l'algorithme (un âge saisi, une liste de notes, un clic…).

→
Traitement

Les instructions : calculs, comparaisons, répétitions. C'est le cœur de l'algorithme.

→
Sorties

Le résultat produit : un texte affiché, une valeur calculée, un élément de la page modifié.

Exemple : pour un convertisseur euros → dollars, l'entrée est un montant en euros et le taux de change, le traitement est une multiplication, la sortie est le montant en dollars.

Les qualités d'un bon algorithme

Précis

Chaque instruction n'a qu'une seule interprétation possible. « Ajouter un peu de sel » n'est pas précis ; « ajouter 5 g de sel » l'est.

Fini

Il s'arrête toujours au bout d'un nombre fini d'étapes. « Tant que la pâte n'est pas parfaite, pétrir » risque de ne jamais se terminer.

Ordonné

L'ordre des instructions compte : on ne met pas le gâteau au four avant d'avoir mélangé les ingrédients.

L'ordinateur ne devine rien

Un humain comprend « prends un verre dans le placard » même si la porte est fermée : il l'ouvre sans qu'on le lui dise. Un ordinateur, non. Il faut tout expliciter : ouvrir la porte, prendre le verre, refermer la porte. C'est la principale difficulté quand on débute.

Étapes disponibles

Votre algorithme

    Remarquez que « appliquer un filtre » et « écrire la légende » pourraient aussi s'échanger dans l'application réelle : il existe souvent plusieurs algorithmes corrects pour un même problème. Ici, on a choisi de suivre l'ordre des écrans de l'application.

    Le pseudo-code : réfléchir avant de coder

    Pour écrire un algorithme sans se soucier de la syntaxe d'un langage, on utilise le pseudo-code : du français structuré avec quelques mots-clés en majuscules. Il n'est pas exécutable, mais il se traduit ensuite presque mot pour mot en JavaScript, en Python ou en PHP.

    Pseudo-code

    ALGORITHME Conversion
VARIABLES euros, dollars : réels
DÉBUT
  euros ← 50
  dollars ← euros × 1.08
  AFFICHER dollars
FIN

    JavaScript

    // Conversion
let euros = 50;
let dollars = euros * 1.08;
console.log(dollars);

    Quelques conventions que l'on retrouvera tout au long du parcours :

    Pseudo-code JavaScript Rôle
    x ← 5 x = 5; Affectation : ranger 5 dans la variable x.
    AFFICHER x console.log(x); Sortie : montrer une valeur (ici dans la console).
    LIRE x x = prompt("…"); Entrée : demander une valeur à l'utilisateur·rice.
    // commentaire // commentaire Note pour les humains, ignorée par l'ordinateur.

    Où s'exécute le JavaScript ?

    Dans ces pages, les zones « À vous de jouer » exécutent votre code et affichent le résultat de console.log() juste en dessous. Dans un vrai projet, ce même résultat apparaît dans la console des outils de développement du navigateur (F12 puis onglet Console), comme vu dans le TD Premières pages JavaScript.

    Laquelle de ces instructions est assez précise pour un ordinateur ?

    Exactement : « inférieur à 18 » est une comparaison que l'ordinateur sait évaluer. « L'air jeune », « assez longtemps » ou « sympa » sont des jugements humains : il faudrait les traduire en règles chiffrées.

    La méthode en 4 étapes

    1. Comprendre le problème : quelles sont les entrées ? quelle sortie attend-on ?
    2. Résoudre à la main un exemple concret, sur papier.
    3. Écrire le pseudo-code en généralisant ce que vous avez fait à la main.
    4. Traduire en JavaScript et tester avec plusieurs valeurs, y compris les cas limites (0, valeur négative, liste vide…).
