Chapitre 6

Les fonctions : découper pour mieux régner

Quand un programme grossit, on le découpe en petits sous-programmes, chacun chargé d'une seule tâche et doté d'un nom clair. Ce sont les fonctions. Vous en utilisez déjà : console.log(), Math.floor(), parseInt()…

Une fonction, c'est une machine

Paramètres

Les valeurs qu'on donne à la fonction quand on l'appelle : ses ingrédients.

→
Corps de la fonction

L'algorithme, écrit une seule fois, qui travaille sur les paramètres.

→
Valeur de retour

Le résultat que la fonction renvoie avec return, à l'endroit où on l'a appelée.

Définir, puis appeler

Pseudo-code

FONCTION prixTTC(prixHT) : réel
  RETOURNER prixHT × 1.2
FIN FONCTION

AFFICHER prixTTC(50)    // 60
AFFICHER prixTTC(10)    // 12

JavaScript

function prixTTC(prixHT) {
  return prixHT * 1.2;
}

console.log(prixTTC(50)); // 60
console.log(prixTTC(10)); // 12
  • Définir une fonction (le mot-clé function) ne l'exécute pas : on explique seulement comment faire.
  • Appeler la fonction (son nom suivi de parenthèses) l'exécute. On peut l'appeler autant de fois qu'on veut, avec des valeurs différentes.
  • prixHT est un paramètre : une variable qui reçoit, à chaque appel, la valeur placée entre les parenthèses (l'argument).

Exécution pas à pas : le voyage d'un appel

Observez bien le « saut » : lors d'un appel, l'exécution part dans la fonction, puis revient à l'endroit de l'appel avec la valeur renvoyée. Les variables créées dans la fonction (prixHT, ttc) n'existent que pendant l'appel : on dit qu'elles sont locales.

return ou console.log ?

La confusion n° 1

console.log() affiche une valeur pour l'humain qui regarde la console, puis l'oublie. return renvoie une valeur au programme, qui peut la ranger dans une variable, la comparer, la réutiliser dans un calcul. Une fonction qui calcule quelque chose doit renvoyer son résultat ; c'est à celui qui l'appelle de décider s'il veut l'afficher.

✘ Affiche, mais ne renvoie rien

function double(n) {
  console.log(n * 2);
}
let x = double(5) + 1;
// affiche 10, puis x vaut NaN :
// double(5) vaut undefined !

✔ Renvoie le résultat

function double(n) {
  return n * 2;
}
let x = double(5) + 1;
// x vaut 11
console.log(x);

Autre point important : return arrête immédiatement la fonction. Les lignes situées après un return exécuté ne sont jamais lues.

Qu'affiche ce programme ?

function signe(n) {
  if (n < 0) {
    return "négatif";
  }
  return "positif ou nul";
}
console.log(signe(-4));

-4 < 0 est vrai : le premier return est exécuté et la fonction s'arrête aussitôt. Le second return n'est atteint que si la condition est fausse : pas besoin de else !

Pourquoi découper en fonctions ?

Ne pas se répéter

Un calcul utilisé à dix endroits est écrit une seule fois. Une correction se fait à un seul endroit.

Lisibilité

if (estMajeur(age)) se lit comme une phrase. Un bon nom de fonction est un verbe qui dit ce qu'elle fait.

Tester séparément

Chaque fonction se teste toute seule, avec quelques valeurs, avant de l'assembler avec le reste du programme.

Et dans une page web ?

C'est avec les fonctions que JavaScript devient interactif : on écrit une fonction, puis on demande au navigateur de l'appeler quand l'utilisateur·rice clique sur un bouton. Le TD Fonctions en JavaScript et le TD Interaction DOM vous montrent comment.

À retenir

  • On définit une fonction une fois, on l'appelle autant qu'on veut.
  • Les paramètres reçoivent les valeurs données à l'appel ; les variables d'une fonction sont locales.
  • return renvoie le résultat et termine la fonction ; console.log ne fait qu'afficher.
